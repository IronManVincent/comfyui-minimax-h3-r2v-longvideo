# 项目开发流程与规范

本文档记录项目的开发流程、发版规范、检查清单和经验教训，确保项目长期稳定维护。

---

## 一、开发工作流

### 需求处理流程

```
用户提出需求 → 理解反馈 → 调研社区方案 → 设计方案 → 用户确认 → 实施变更 → 自查验证 → 自动测试 → 监控状态 → 生成报告 → 用户验收 → 考虑推送
```

### 关键原则

1. **先确认再动手**：任何方案实施前，必须得到用户明确同意
2. **充分调研**：不闭门造车，优先采用官方/社区成熟方案
3. **变更后自查**：工作流修改后必须验证所有节点连接、参数、脱敏状态
4. **主动监控**：提交任务后按约定频率轮询状态，不需用户催促
5. **质量优先**：不急于交付，确保产物合格后再提交用户验收

## 三、版本管理规范

### 3.1 版本号规则

采用语义化版本：`主版本.次版本.修订号`

- **主版本**：不兼容的架构变更（如动态分镜系统）
- **次版本**：向下兼容的功能新增（如音频优化、新节点）
- **修订号**：向下兼容的问题修复（如连接修复、参数调整）

### 3.2 本地版本保留

- 只保留：当前开发/测试版 + 上一个稳定版
- 更早版本：删除（GitHub archive目录已有备份）

### 3.3 GitHub版本保留

- `workflows/` 根目录：最新稳定版 + 上一个稳定版
- `workflows/archive/`：所有历史版本归档

## 四、测试规范

### 4.1 测试参考图

- **唯一授权测试图**：`campus_girl_final_00001_.png`
- 来源：output目录（Z-Image Turbo生成），input目录为工作副本
- 如input目录不存在，从output目录拷贝
- 未经用户明确同意，不得使用其他图片

### 4.2 任务监控策略

- 提交后前3分钟：每1分钟轮询一次（报错高发期）
- 3分钟后正常执行：每5分钟轮询一次
- 任务失败：立即分析原因，研究解决方案
- 任务成功：生成报告，分析产出质量，推送用户验收

### 4.3 产出质量自查

任务跑通后，交付用户前必须自查：
- [ ] 视频画面是否完整（无黑屏、无截断）
- [ ] 各分镜画面是否有重复/倒放现象
- [ ] 音频是否存在（无静音段）
- [ ] 音频质量是否衰减严重
- [ ] 分镜衔接是否自然
- [ ] 总时长是否符合设置
- 自查不通过：迭代优化，直至合格再交付

## 五、经验教训记录

### 案例1：发版遗漏关联文档更新（2026-09-01）

**问题**：v1.4.1发版时，只更新了README和CHANGELOG，遗漏了examples.md和archive/README.md，导致文档版本不一致。

**根因**：
- 发版时急躁，凭记忆操作，没有建立检查清单
- 没有意识到文档之间的关联关系

**影响**：
- 社区用户看到examples.md中还是v1.4.0的旧内容
- archive目录README未记录v1.3.1归档

**固化措施**：
- 建立强制发版检查清单（见第二章）
- 每次发版必须逐项核对，全部打勾后才能推送
- 文档更新清单固定化：README + CHANGELOG + examples.md + archive/README

---

### 案例2：工作流变更后自查不充分（多次出现）

**问题**：多次出现节点未连接、参考图不存在、CreateVideo api_node=False等低级错误，导致测试任务失败。

**根因**：
- 变更后没有逐项验证节点连接
- 没有验证参考图路径是否存在
- 急于交付，跳过自查环节

**固化措施**：
- 工作流修改后必须执行自查清单
- 验证所有节点连接、参数设置、参考图状态
- 确认无误后再交付用户测试

---

### 案例3：任务监控不主动（多次出现）

**问题**：提交任务后没有主动轮询状态，需要用户反复催促"任务跑完没有"。

**根因**：
- 没有形成主动监控的习惯
- 轮询策略没有严格执行

**固化措施**：
- 建立固定轮询策略（前3分钟1分钟一次，之后5分钟一次）
- 提交任务后立即启动监控，不需用户提醒

**原则**：文档各司其职，不重复不遗漏。项目层面内容放README，具体产出示例放examples.md，版本历史放CHANGELOG。

## 七、纠错机制

当用户审查发现问题时，按以下流程处理：

1. **立即响应**：承认问题，不辩解
2. **开启自查**：检查问题影响范围，是否还有其他同类问题
3. **根因分析**：分析为什么会出现这个问题（流程缺失？检查不到位？急躁？）
4. **经验固化**：将解决方案转化为检查清单或流程规范，写入本文档
5. **流程更新**：更新相关检查清单，确保后续不再犯同类错误
6. **持续执行**：在后续工作中严格执行固化的经验

**目标**：同一个错误不犯第二次，每次问题都转化为流程改进。
